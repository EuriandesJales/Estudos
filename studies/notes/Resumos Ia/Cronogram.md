# Framework prático:

# Critério de Suficiência Operacional (CSO)

Você só pode continuar aprofundando um tema SE ele falhar nesses critérios.

---

# CAMADA 1 — Compreensão Conceitual

Perguntas:

|Critério|Objetivo|
|---|---|
|consigo explicar isso sem copiar documentação?|entendimento|
|consigo descrever os componentes principais?|arquitetura|
|sei o que o sistema resolve?|propósito|
|sei os gargalos/limitações?|maturidade|

Se SIM:

# pare de estudar teoria básica.

---

# CAMADA 2 — Capacidade Operacional

Perguntas:

|Critério|Exemplo|
|---|---|
|consigo instalar/configurar do zero?|Docker, Linux, banco|
|consigo resolver falhas comuns?|logs, debug|
|consigo integrar com outro sistema?|API, rede|
|consigo automatizar o fluxo básico?|script, compose|

Se SIM:

# você já possui competência operacional inicial.

---

# CAMADA 3 — Produção Real

A pergunta mais importante:

## “eu conseguiria usar isso num projeto REAL?”

Não:

- perfeitamente.
- elegantemente.
- no nível de especialista.

Apenas:

# funcionalmente.

---

# Exemplo aplicado ao:

Docker

Você NÃO precisa:

- entender internals completos do overlayfs,
- estudar namespaces por 6 meses,
- dominar OCI profundamente.

- subir serviços,
- persistir dados,
- integrar containers,
- usar volumes,
- debugar rede,
- automatizar compose,

então:

# Docker já pode entrar no currículo.
